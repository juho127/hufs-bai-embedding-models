# 모델 카드: HUFS BAI Legal Embed 1B v0.1

[English](model-card.md) · **한국어**

## 모델 설명

**`hufs-bai-legal-embed-1b-v0.1`**은 **한국외국어대학교 비즈니스AI연구실(HUFS Business AI Lab)**의 한국어 법률 도메인 임베딩 모델입니다. 질문과 문단을 벡터로 변환하여 의미 기반 검색과 RAG에 활용할 수 있습니다. NVIDIA Nemotron-3-Embed-1B-BF16의 전체 파라미터를 학습하여 법률 검색 검증셋의 nDCG@10을 **0.7895에서 0.8293으로 개선**했습니다.

| 항목 | 내용 |
|---|---|
| 공개 버전 | [v0.1.0](https://github.com/juho127/hufs-bai-embedding-models/releases/tag/v0.1.0) |
| 기반 모델 | [nvidia/Nemotron-3-Embed-1B-BF16](https://huggingface.co/nvidia/Nemotron-3-Embed-1B-BF16) |
| 기반 revision | `c0c9fea93ea424587517f2c59e20db9f1d6bf615` |
| 파라미터 수 | 1,140,918,272 |
| 인코더 | Ministral3, 양방향 attention (`is_causal=false`) |
| 임베딩 차원 | 2,048 |
| pooling | Mean pooling, 접두어 토큰 포함 |
| 유사도 | 정규화된 벡터의 코사인 유사도 |
| 질문 / 문단 접두어 | `query: ` / `passage: ` |
| 학습·평가 입력 길이 | 접두어를 포함하여 최대 1,536 tokens |
| 가중치 정밀도 | FP32 |
| 모델 라이선스 | OpenMDW 1.1 |

1,536 tokens는 이 모델의 학습·평가에 사용한 설정이며, 기반 모델 구조가 지원하는 최대 길이를 뜻하지 않습니다. 더 긴 입력의 검색 성능은 아직 평가하지 않았습니다.

## 활용 범위

자연어 질문에 맞는 한국어 법률 문단 검색, 법률 문서 모음의 의미 검색, RAG 시스템의 근거 검색에 사용할 수 있습니다. 출력은 임베딩 벡터입니다. 법률 답변 생성이나 문서의 현행성·법적 권위 판정은 이 모델의 기능에 포함되지 않습니다.

평가 자료에는 법률 관련 정책·입법·행정 문서가 포함되어 있습니다. 판례로만 구성된 자료, 다른 전문 도메인이나 언어, 문서 분포가 다른 검색 환경에 적용할 때는 해당 검색 과제에서 성능을 확인해야 합니다.

## 다운로드와 추론

FP32 전체 모델을 파일당 2 GB 미만으로 나누어 공개하며, 설정·토크나이저·라이선스·출처 고지 파일을 함께 제공합니다. 표준 safetensors 분할 파일을 함께 제공하는 인덱스를 통해 자동으로 불러오므로 직접 합칠 필요가 없으며, NVIDIA 기반 모델을 별도로 다운로드할 필요도 없습니다.

[환경 설정 안내](setup.md)에 따라 의존성을 설치한 뒤 실행합니다.

```bash
python scripts/download_release.py --output models/hufs-bai-legal-embed-1b-v0.1
python examples/retrieve.py --model models/hufs-bai-legal-embed-1b-v0.1
```

제공하는 로더는 FP32 가중치를 유지합니다. 지원되는 CUDA 장치에서는 BF16 autocast를 사용하고, CPU에서는 FP32로 연산합니다. 질문과 문단 접두어가 한 번씩 적용되도록 체크포인트의 `encode_query`와 `encode_document`를 사용합니다. 예제는 벡터를 정규화한 뒤 코사인 유사도로 검색합니다. 체크섬과 배포 파일 구성은 [배포 안내](distribution.md)를 참고하세요.

## 학습 데이터

**AI Hub**가 제공하는 **금융·법률 문서 기계독해 데이터**, [데이터셋 71610](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=71610)의 법률 자료를 사용했습니다. 학습에는 문단 추출형·절차형 질문인 type 1·5를 사용했으며, 검색 후보에는 법률 질문 type 1·2·4·5의 비표 문단을 포함했습니다.

| 항목 | 수 |
|---|---:|
| 준비한 학습 질문·문단 쌍 | 89,979 |
| 실제 학습에 사용한 쌍 | 89,898 |
| 배치 호환성 규칙에 따라 제외된 단독 쌍 | 81 |
| 검증 질문 | 500 |
| 확보한 최종 test 질문 | 1,000 |
| 검색 후보 문단 | 66,895 |
| 검증 문서군 | 452 |

문서 ID, 제목, 중복 질문·문단의 연결 관계를 이용해 문서군을 구성한 뒤 데이터를 분리했습니다. 품질 검토에 사용한 문서군은 최종 test에서 제외했습니다. AI Hub 원문, 가공한 학습·평가 텍스트, 비공개 검토 주석은 배포하지 않습니다. 공개 전처리 코드는 처리 방법을 제공하며, 보고된 데이터 분할을 정확히 재현하려면 원본 자료와 정제 주석이 추가로 필요합니다.

## 학습 방법

질문에서 문단을 찾는 방향의 `CachedMultipleNegativesRankingLoss`로 전체 파라미터를 학습했습니다. 논리 배치 내 다른 질문의 정답 문단을 네거티브로 사용합니다. 동일 문서군이나 문단 ID를 공유하거나, 정규화한 질문·문단이 정확히 중복되는 쌍은 한 배치에서 분리합니다. 이 검사는 확인 가능한 충돌을 줄이며, 의미상 관련된 모든 대체 정답을 식별하는 방법은 아닙니다.

| 설정 | 값 |
|---|---|
| epoch / seed | 1 / 42 |
| 최적화 step | 738 |
| learning rate | `2e-6` |
| 논리 배치 / microbatch | 128 / 4 |
| 최대 입력 길이 | 1,536 |
| loss scale | 20 |
| warmup ratio | 0.1 |
| weight decay | 0.01 |
| gradient clipping norm | 1.0 |
| optimizer | AdamW |
| 학습 파라미터 수 | 1,140,918,272 |
| 파라미터·optimizer state 정밀도 | FP32 |
| forward 연산 | BF16 autocast |
| 학습 장치 | NVIDIA RTX A6000 48 GB, 1장 |
| 학습 시간 | 18,446초, 약 5.12시간 |
| PyTorch 최대 CUDA allocated 메모리 | 29.54 GiB |
| PyTorch | `2.11.0+cu128` |

원래 저장된 체크포인트 크기는 4,580,826,739 bytes입니다. 공개 패키지는 FP32 텐서를 보존한 채 가중치 파일을 분할하고 배포 정보를 추가합니다. 최대 CUDA allocated 메모리는 PyTorch 텐서 할당량이며 프로세스 전체나 시스템 메모리 사용량은 아닙니다. 학습 체크포인트를 저장하고 다시 불러왔을 때 파라미터 값이 정확히 일치하는지 확인했습니다.

## 평가

원본과 학습 모델을 동일한 RTX A6000에서 검증 질문 500개와 검색 후보 66,895개 전체로 평가했습니다. 두 모델 모두 FP32 파라미터로 불러와 BF16 autocast, SDPA attention, 배치 크기 8, 최대 길이 1,536을 적용했습니다. 정규화한 벡터의 정확 코사인 검색으로 순위를 계산했습니다.

| 지표 | 원본 모델 | HUFS BAI Legal Embed 1B | 절대 개선량 | 개선량 95% 신뢰구간 |
|---|---:|---:|---:|---:|
| nDCG@10 | 0.7895 | **0.8293** | +0.0398 | [+0.0221, +0.0581] |
| MRR@10 | 0.7441 | **0.7897** | +0.0455 | [+0.0241, +0.0674] |
| Recall@10 | 0.928 | **0.950** | +0.022 | [+0.0021, +0.0420] |
| Recall@50 | 0.980 | **0.988** | +0.008 | [−0.0020, +0.0197] |

452개 문서군을 단위로 paired bootstrap을 10,000회 수행하여 신뢰구간을 계산했으며, 질문 수로 가중하고 seed 42를 사용했습니다. nDCG@10의 상대 개선율은 **5.04%**입니다. Recall@50의 점추정치는 높아졌지만 신뢰구간에 0이 포함됩니다.

하나의 학습 설정과 seed로 얻은 검증셋 결과입니다. 여러 seed의 반복 평가는 아직 수행하지 않았습니다. [평가 상세](evaluation.md)에 평가 절차와 통계적 비교 방법이 정리되어 있으며, [결과 JSON](../results/initial_dev_results.json)에서 반올림 전 수치를 확인할 수 있습니다.
