# 법률 검색 평가

## 연구 질문과 초기 결과

연구 질문은 **한국어 법률 데이터에 대한 도메인 학습이 원본 Nemotron보다 관련 근거 문단을 잘 찾게 하는가**입니다. 주지표는 nDCG@10이며, LoRA 대비 원본과 전체 학습 대비 원본을 각각 평가합니다. 두 학습 방법끼리의 비교와 자원 사용량은 추가 분석입니다.

전체 파라미터 학습 1 epoch 후 검증셋 nDCG@10은 **0.7895 → 0.8293**, 상대 **5.04%** 향상됐습니다.

| 지표 | 원본, A6000 | 전체 학습, A6000 | 절대 개선량 | 개선량 95% CI |
|---|---:|---:|---:|---|
| **nDCG@10** | 0.789522 | **0.829304** | **+0.039782** | **[+0.022083, +0.058146]** |
| MRR@10 | 0.744120 | 0.789668 | +0.045548 | [+0.024106, +0.067428] |
| Recall@10 | 0.928 | 0.950 | +0.022 | [+0.002066, +0.042000] |
| Recall@50 | 0.980 | 0.988 | +0.008 | [−0.002020, +0.019725] |

문서군 단위 paired bootstrap에서 nDCG@10 개선량의 95% 신뢰구간이 0보다 큽니다. Recall@50은 점추정치가 증가했지만 신뢰구간에 0이 포함됩니다.

LoRA도 1 epoch 학습과 검증셋 평가를 완료했습니다.

| 지표 | 원본, GB10 | LoRA, GB10 | 절대 개선량 | 개선량 95% CI |
|---|---:|---:|---:|---|
| **nDCG@10** | 0.790435 | **0.795704** | **+0.005270** | **[−0.007562, +0.017973]** |
| MRR@10 | 0.745353 | 0.749703 | +0.004350 | [−0.010998, +0.019801] |
| Recall@10 | 0.928 | 0.936 | +0.008 | [−0.008114, +0.024291] |
| Recall@50 | 0.980 | 0.980 | 0.000 | [−0.011765, +0.010289] |

LoRA의 nDCG@10 점추정치는 소폭 상승했지만 모든 지표의 개선량 신뢰구간에 0이 포함됩니다. 따라서 이번 초기 실험에서 LoRA의 검색 성능 개선은 통계적으로 확인하지 못했습니다.

전체 학습은 이번 설정에서 더 큰 원본 대비 개선을 보였습니다. 원본도 GPU 및 CUDA 환경에 따라 작은 수치 차이가 있으므로 각 학습 모델은 동일 환경에서 평가한 원본과 비교합니다. 서로 다른 학습률과 하드웨어에서 얻은 이 결과를 LoRA와 전체 학습의 일반적인 우열로 확대하지 않습니다.

기준일은 2026-10-10입니다. 기계가 읽을 수 있는 요약은 [initial_dev_results.json](../results/initial_dev_results.json)에 제공합니다.

## 데이터 구성

AI Hub [금융·법률 문서 기계독해 데이터, 71610](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=71610)에서 법률 자료를 구분하고, 비표 문단을 사용했습니다. 질문·근거 문단의 중복과 관련 문서의 연결 관계를 고려해 데이터셋의 기존 train/validation 구분을 새 문서군 단위 분할로 재구성했습니다.

| 항목 | 구성 |
|---|---|
| 학습 | type 1·5, 89,979쌍 |
| seed 42 학습 노출 | 89,898쌍, 738 step |
| 검증 | 질문 500개, 문서군 452개 |
| 최종 test | 질문 1,000개, 문서군 626개, 아직 평가하지 않음 |
| 검색 후보 | type 1·2·4·5, 정규화 후 중복을 제거한 법률 비표 문단 66,895개 |
| 정답 관련성 | 원 데이터의 질문·근거 문단 연결 |

동일 문서 ID, 정규화 후 동일한 제목·질문·문단, 명시적인 판본 연결 등을 사용해 연결된 문서군을 만들었습니다. 같은 문서군은 train/dev/test에 걸쳐 나누지 않습니다. 품질 검토에 사용한 117개 원문 문서 ID와 연결된 문서군도 최종 test에서 제외했습니다.

검색 후보 집합에는 train/dev/test 문단이 모두 들어가며 모든 질문을 같은 전체 후보 집합에서 평가합니다. 학습에 사용하는 질문·정답 쌍은 train에 한정합니다. type 2·4 문단도 검색 후보에 포함하므로 학습 대상 유형의 문단만 골라 검색하지 않습니다.

원본 ZIP의 무결성, JSON 구조, 질문과 문단 연결, 중복, 토큰 길이를 확인했습니다. 수동 전문가 정답셋을 새로 구축한 것은 아닙니다. LLM의 층화 표본 검토 120건은 정제 규칙을 정하기 위한 점검이었으며, 그 비율을 전체 데이터의 오류율로 보고하지 않습니다.

## 검색 프로토콜

1. 고정 revision의 모델 또는 학습한 체크포인트를 로드합니다.
2. `query: `와 `passage: ` 접두어를 적용하고 mean pooling에 접두어 토큰을 포함합니다.
3. 모든 벡터를 정규화하고, 질문마다 66,895개 문단 전체에 대한 코사인 유사도를 계산합니다.
4. 근사 최근접 탐색 없이 정확한 top 50을 구합니다. 동점은 고정된 후보 순서로 처리합니다.
5. 질문별 점수를 계산한 뒤 질문에 동일한 가중치를 주어 평균합니다.

비교할 모델 모두 FP32 파라미터 로딩, BF16 autocast, SDPA, 평가 batch 8, 최대 길이 1,536을 사용합니다. 질문·후보·정답 및 평가 프로토콜의 해시를 검사해 서로 다른 입력으로 만든 보고서를 비교하지 않습니다. 학습 모델과 원본의 평가 코드, 접두어, 검색 방식은 같습니다.

| 지표 | 의미 |
|---|---|
| nDCG@10 | 상위 10개에서 관련 문단을 얼마나 높은 순위에 찾는가 |
| MRR@10 | 상위 10개에서 첫 관련 문단의 순위 역수 |
| Recall@10 | 정답 관련 문단 중 상위 10개에 찾은 비율 |
| Recall@50 | 정답 관련 문단 중 상위 50개에 찾은 비율 |

nDCG의 gain은 `2**relevance - 1`이며, 정답에 표시되지 않은 문단은 평가에서 비관련으로 처리합니다. 제공된 원 데이터 정답 외에도 유효한 근거가 존재할 수 있어 이 평가는 원 데이터의 근거 문단을 찾는 성능을 측정합니다.

## 통계적 비교

동일 질문에 대한 학습 모델과 원본의 점수 차이를 계산하고, **문서군 452개를 복원추출하는 paired cluster bootstrap**을 10,000회 수행했습니다. seed는 42, 난수 생성기는 NumPy PCG64입니다. 각 표본에서 문서군에 속한 질문들을 함께 선택하고 질문 수로 가중한 평균을 계산합니다. 보고하는 95% 구간은 percentile 방식입니다.

신뢰구간은 이 검증 질문 집합의 문서군 표본 변동을 반영합니다. 학습 seed의 변동을 추정하는 값은 아닙니다. 여러 비교 전체에 대한 동시 신뢰구간도 아닙니다.

## 평가 재현

먼저 [환경 설정](setup.md)에 따라 의존성과 모델을 준비하고, 이용 권한이 있는 자료로 다음 파일을 만듭니다.

| 파일 | JSONL의 필수 항목 |
|---|---|
| `corpus.jsonl` | 문단별 `id`, `text` |
| `dev/queries.jsonl` | 질문별 `id`, `text`, 문서군 단위 비교를 위한 `group_id` |
| `dev/qrels.jsonl` | `query_id`, `corpus_id`, `relevance` |

아래 경로는 사용자가 준비할 입력과 출력의 예시입니다. 실제 법률 데이터는 저장소에 포함하지 않습니다.

```bash
python scripts/evaluate.py \
  --model models/nemotron-3-embed-1b-bf16 \
  --corpus data/processed/legal_v1/corpus.jsonl \
  --queries data/processed/legal_v1/dev/queries.jsonl \
  --qrels data/processed/legal_v1/dev/qrels.jsonl \
  --output results/local/base_dev.json \
  --max-seq-length 1536 --batch-size 8 \
  --dtype float32 --autocast bfloat16 --attention sdpa
```

학습 체크포인트를 같은 설정으로 평가해 `candidate_dev.json`을 만든 뒤 비교합니다.

```bash
python scripts/compare_runs.py \
  --baseline results/local/base_dev.json \
  --candidate results/local/candidate_dev.json \
  --output results/local/candidate_minus_base_dev.json \
  --unit group --replicates 10000 --seed 42
```

선택적인 `--embedding-cache-dir` 옵션으로 후보 임베딩을 재사용할 수 있습니다. 모델 파일·후보 집합·평가 설정을 확인한 캐시만 사용하며 질문 임베딩은 매번 계산합니다.

## 결과의 적용 범위와 다음 평가

현재 결과는 seed 42, 1 epoch의 검증셋 결과입니다. 학습률 탐색이나 여러 seed에 걸친 재현성을 확인한 최종 성능이 아닙니다. 최종 test는 두 학습 방식의 설정을 확정한 뒤 평가하며, 모델 선택에는 사용하지 않습니다.

자료는 입법·정책·행정·연구 보고서를 많이 포함하고 발행연도는 2006~2022년에 걸쳐 있습니다. 따라서 확인된 성과는 해당 자료의 질문에 대한 근거 문단 검색 향상입니다. 판례 검색 전반, 최신 법령의 정확성, 법률 상담 및 생성 답변의 품질은 이번 평가에 포함하지 않았습니다.
